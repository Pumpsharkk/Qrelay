Q-RELAY

Quantum-Safe Cross-Chain & Wallet Security Engine

Today's blockchains sign with ECDSA or Ed25519. A large quantum computer running Shor's algorithm can break those signatures. Q-Relay is a desktop app and an open-source CLI that measures your quantum exposure, adds post-quantum signatures, and moves long-term assets into a quantum-safe vault.

Risk scanner live

Real on-chain analysis. Your browser queries a public RPC node directly: EVM bytecode is disassembled and Solana programs are parsed byte by byte. No backend, nothing is stored. The score is a transparent heuristic built from the findings listed below it.

Hybrid entropy generator

Generates 256 bits of key material in your browser. It mixes OS entropy (Web Crypto) with quantum random numbers from ANU QRNG through HKDF-SHA256, so a failure in one source cannot weaken the result. The ANU API needs a free API key; without one, only OS entropy is used and the output says so.

Four modules

One engine, four jobs: measure the risk, sign safely, generate keys, and store the assets that matter.

MODULE A

Q-Shield

Hybrid signature layer. Every transaction carries a standard signature plus a second, NIST-approved post-quantum signature (ML-DSA, formerly CRYSTALS-Dilithium, or FN-DSA, formerly Falcon).

The contract or relay network approves the transaction only when both signatures are valid. It works with your existing Phantom or MetaMask wallet through a hybrid signature wrapper.

MODULE B

Quantum entropy key generator

Standard wallets build seed phrases from pseudo-random (PRNG) math. Q-Relay feeds key generation with entropy from quantum fluctuations and atmospheric noise: the ANU QRNG API or local quantum hardware.

The result is a key generated from a source that is unpredictable by physics, not only by computation.

MODULE C

Smart contract PQC vulnerability scanner

Paste a Solana or EVM contract address. Q-Relay inspects its signature verification, hash use and authority keys, then reports how exposed the contract would be on Q-Day as a percentage Quantum Risk Score.

MODULE D

Post-quantum vault

A multi-layer cold/hot hybrid panel for high-value assets such as NFTs and large token holdings. Move existing assets into a quantum-safe smart vault in one click, protected by time-lock and lattice-based cryptography.

User flow

From install to a fully isolated vault, in four steps.

  1. Install. Install the Q-Relay desktop app and connect your wallet (Phantom, MetaMask) with read-only permission.
  2. Analyze. See the quantum risk map of your assets and of every contract you have interacted with, on a single screen.
  3. Shield. Before a critical transfer, enable Q-Shield. The transaction goes to the mempool with a quantum-resistant hybrid signature.
  4. Store safely. Move long-term holdings into a new-generation quantum vault created with QRNG entropy, isolating them from future Shor's algorithm attacks.

Engineering reality check

Design decisions we are building around, so the security claims stay honest.

Q-Shield needs an on-chain account

Ethereum and Solana validators check only ECDSA or Ed25519. A second signature is invisible to the chain unless funds sit in a smart account that requires both: ERC-4337 on EVM, a custom program on Solana. Modules A and D therefore merge into one PQ-verifying vault. Dilithium verification is gas-expensive on EVM; hash-based schemes (Winternitz-style) are more practical on Solana today.

QRNG is mixed, never alone

Pulling entropy over the internet makes a third party part of your trust. The OS CSPRNG is already practically unpredictable. Q-Relay combines QRNG output with OS entropy through HKDF or XOR, so one failing source cannot weaken the key.

Hashes are not the weak point

SHA-256 and Keccak stay safe: Grover's algorithm cuts a 256-bit hash to about 128 bits of strength, which is still strong. The real risks:

  • ECDSA and Ed25519 use (ecrecover, ed25519 verification)
  • BLS and pairing-based constructions, including KZG
  • Addresses whose public key is already exposed
  • Admin and upgrade-authority keys

The risk score is built on these. On EVM the scanner looks for precompile calls (0x01 ecrecover, 0x08 pairing). On Solana it checks upgrade authority and ed25519 program use.

Use the official names

ML-DSA (Dilithium, FIPS 204), SLH-DSA (SPHINCS+, FIPS 205), FN-DSA (Falcon). Falcon signatures are small but need floating point, so implementation is delicate. liboqs suits prototypes; pure-Rust implementations exist for production. Do not put real funds in the vault before an independent audit.

Build order

  1. CLI scanner (Module C). Stores no keys, so it carries no risk. Easiest to spread on GitHub and the most distinctive part of the idea.
  2. Hybrid-entropy key generator (Module B).
  3. PQ vault contract (Modules A + D). Hardest and riskiest part. Audit first.
  4. Tauri desktop interface. Last.
